# Importing Analytical Data and Metadata

**Not sure which importer to use?** See [Import and prepare data
files](https://slinghub.github.io/MRMhub/quant/articles/manual-05a-which-importer.md)
for a visual decision flowchart.

**Caution.** Do not manually edit data files exported from instrument
software before importing. Manual edits can corrupt the file structure
or introduce accidental errors — MRMhub emphasises reproducible,
automated workflows.

## Part 1: Importing Analytical Data

Analytical data (preprocessed peak areas from mass spectrometry
experiments) can be imported from different sources.

Data files present in a folder can also be imported and merged. This is
useful when raw data processing is split into batches, producing
separate result files.

### Supported Formats

| Source | MRMhub function | Details | Extension |
|----|----|----|----|
| Agilent MassHunter | [`import_data_masshunter()`](https://slinghub.github.io/MRMhub/quant/reference/import_data_masshunter.md) | Flat and nested tables from MassHunter Quant. | .csv |
| MRMhub | [`import_data_mrmhub()`](https://slinghub.github.io/MRMhub/quant/reference/import_data_mrmhub.md) | Long format output format | .csv or .tsv |
| Skyline | [`import_data_skyline()`](https://slinghub.github.io/MRMhub/quant/reference/import_data_skyline.md) | Skyline Small Molecule Transition Results (long format) |  |
| Generic wide CSV | [`import_data_csv_wide()`](https://slinghub.github.io/MRMhub/quant/reference/import_data_csv_wide.md) | Samples/analyses as rows and features as columns. Can contain columns with specific sample annotations. | .csv |
| Generic long CSV | [`import_data_csv_long()`](https://slinghub.github.io/MRMhub/quant/reference/import_data_csv_long.md) | Long-format table with each row being a unique `analysis_id` and `feature_id` pair and additional columns representing feature variables and sample/method information | .csv |

### Metadata Within Analytical Results

When the analytical results contain metadata, such as sample and feature
annotations, these can be imported as metadata in the `MRMhubExperiment`
object as well. The imported metadata is checked for integrity and
consistency (see [Metadata
Import](https://slinghub.github.io/MRMhub/quant/articles/manual-06-metadata-import.md))
and then added to the annotation tables within the `MRMhubExperiment`.
To include available metadata, set the argument
`import_metadata = TRUE`.

### MRMhub (INTEGRATOR output)

Long-format output files produced by INTEGRATOR — the peak integration
component bundled with this project — can be imported directly. Metadata
embedded in the data file (`qc_type`, `batch_id`, `analysis_order`,
retention times, m/z values) is imported alongside the peak areas when
`import_metadata = TRUE`.

``` r

library(mrmhub)
filepath <- system.file("extdata/MRMhub_demo.tsv", package = "mrmhub")
myexp <- MRMhubExperiment()

myexp <- import_data_mrmhub(myexp, filepath, import_metadata = TRUE)
```

### Agilent MassHunter Quantitative

Peak integration results exported from Agilent MassHunter Quant in the
CSV format can be imported. Samples must be present in rows, features as
columns. Import of qualifier results is supported. Sample, method and
result metadata present in the files can also be imported
(`import_metadata = TRUE`).

``` r

filepath <- system.file("extdata/MHQuant_demo.csv", package = "mrmhub")
myexp <- MRMhubExperiment()

myexp <- import_data_masshunter(myexp, filepath, import_metadata = TRUE)
```

### Skyline Molecule Transition Results

Small molecule peak integration results from
[Skyline](https://skyline.ms/) can be imported using long-format CSV
reports. To uniquely define `feature_id`s, the CSV file must include the
`Molecule Name` along with either the corresponding precursor and
product m/z values, or their names. The `analysis_id` is mapped from the
`Replicate Name` column, which must also be present in the CSV file.

During the import process, unique `feature_id`s are generated by
appending either the precursor/product names or m/z values to
the `Molecule Name`, unless the `Molecule Name` alone uniquely
identifies the features. This behavior is controlled by
the `transition_id_columns` argument described below. Sample, method,
and result metadata present in the files can also be imported by setting
`import_metadata = TRUE`. For more details, refer to the documentation
of the
[`import_data_skyline()`](https://slinghub.github.io/MRMhub/quant/reference/import_data_skyline.md)
function.

To export results from Skyline: Navigate to “File” \> “Export” and
select ‘Molecule Transition Results’ format. Ensure your export includes
`Replicate Name`, `Molecule Name`, and either `Precursor Mz` and
`Product Mz,` or `Precursor Name` and `Product Name`. Also, export at
least one feature variable like `Area` or `Retention Time (RT)`.

``` r

filepath <- system.file("extdata/Skyline_MoleculeTransitionResults.csv", package = "mrmhub")
myexp <- MRMhubExperiment()

myexp <- import_data_skyline(myexp, 
                             filepath, 
                             import_metadata = TRUE, 
                             transition_id_columns = "mz" )
```

### Generic Wide-Format CSV Files

Analysis results, whether raw intensities (e.g., peak areas) or
preprocessed data (e.g., concentrations), can be provided as plain
wide-format CSV tables. In these tables, analyses (samples) should be
arranged in rows, and features in columns. The specific data type in the
table (e.g., area or concentration) is defined using the `variable_name`
argument.

``` r

filepath <- system.file("extdata/plain_wide_dataset.csv", package = "mrmhub")
myexp <- MRMhubExperiment()

myexp <- mrmhub::import_data_csv_wide(
  myexp, 
  path = filepath,
  variable_name = "area", 
  import_metadata = TRUE)
```

### Generic Long-Format CSV Files

Analysis results containing various feature variables (e.g., peak areas,
retention times) can be provided as generic long-format CSV tables. In
this format, each row represents a unique observation of a feature-value
pair for a given sample, while additional columns capture feature
variables as well as sample- or method-related metadata.

This long-format structure is a common export format supported by many
vendor and open-source software tools for both targeted and untargeted
raw data processing.

By default, the CSV file must include at least the following columns:
`analysis_id`, `feature_id`, and one feature variable column such as
`area`. Additional metadata and feature variable columns are also
supported — please refer to the documentation for
[`import_data_csv_long()`](https://slinghub.github.io/MRMhub/quant/reference/import_data_csv_long.md)
for further details.

If your CSV file uses different column names, you can import it by
specifying a column name mapping. This mapping associates the MRMhub
expected column names with the corresponding column names in your CSV
file (refer to the MRMhub Manual for details).

The column mapping is defined as a named vector, where the names
correspond to the MRMhub column names and the values correspond to the
column names in your CSV.

``` r

 file_path <- system.file("extdata", "plain_long_dataset.csv", package = "mrmhub")

 mexp <- MRMhubExperiment()

# Define a column mapping, right side is the column name in the CSV file
col_map <- c(
  "analysis_id" = "raw_data_filename",
  "qc_type" = "qc_type",
  "feature_id" = "feature_id",
  "feature_class" = "feature_class",
  "istd_feature_id" = "istd_feature_id",
  "qc_type" = "qc_type",
  "feature_rt" = "rt",
  "feature_area" = "area")

# Import data
 mexp <- import_data_csv_long(
   data = mexp,
   path = file_path,
   column_mapping = col_map,
   import_metadata = TRUE)
```

### Multiple Files Import and Merging

Multiple data files can be imported and merged. Users can either provide
a list of file paths or specify a folder path to import all data files
within that directory. This support for multiple files is useful when
raw data processing is divided into batches, leading to separate result
files.

The imported merged data is checked for consistency, ensuring that each
analysis ID and feature ID pair is unique. This means that the same
feature cannot be reported multiple times within the same analysis,
which can happen, for example, if the same feature in the same sample
was integrated in different raw data processing batches.

## Part 2: Preparing and Importing Metadata

Metadata refers to the annotations that describe your analytical data at
the sample level and feature level. This includes sample types, batch
assignments, internal standard assignments, concentrations, and more.

Which metadata tables you need depends on your processing workflow. See
[Data
Structures](https://slinghub.github.io/MRMhub/quant/articles/manual-01-data-structure.md)
for an overview of all metadata categories.

**Integrity matters.** Metadata and data must be consistent — matching
`analysis_id` and `feature_id` values across all tables. MRMhub checks
for completeness and consistency on import and reports errors, warnings,
and notes.

### Generating Metadata Templates

MRMhub provides Excel templates with column headers and instructions.
Start from a template and fill in the required information:

``` r

# Save all metadata templates to the current directory
save_metadata_templates()
```

This creates Excel files for each metadata type: analyses, features,
internal standards, response curves, and QC concentrations.

**MSOrganiser template**

An Excel workbook (`.xlsx`) that combines all metadata into one file:

``` r

save_metadata_msorganiser_template()
```

See [Metadata
Import](https://slinghub.github.io/MRMhub/quant/articles/manual-06-metadata-import.md)
for instructions on filling out the MSOrganiser template.

### Importing Metadata Table by Table

Import individual metadata tables from CSV or Excel files:

``` r

# Analysis-level metadata (sample types, batch IDs, run order)
mexp <- import_metadata_analyses(mexp, 
                                 path = "datasets/analysis_metadata.csv", 
                                 excl_unmatched_analyses = TRUE, 
                                 ignore_warnings = TRUE)

# Feature-level metadata (compound names, ISTD assignments)
mexp <- import_metadata_features(mexp, 
                                 path = "datasets/feature_metadata.csv",
                                 ignore_warnings = TRUE)
```

Import from Excel workbook sheets:

``` r

# Internal standard concentrations
mexp <- import_metadata_istds(mexp, 
                              path = "datasets/metadata_tables.xlsx", 
                              sheet = "ISTDs",
                              ignore_warnings = TRUE)
```

### Importing Metadata from R Data Frames

Metadata can also be provided directly as R data frames — useful when
metadata comes from a database, LIMS, or is prepared programmatically:

``` r

# Read QC concentration data and import
df_qcinfo <- readr::read_csv("datasets/qc_metadata.csv")
mexp <- import_metadata_qcconcentrations(mexp, table = df_qcinfo)
```

### Importing from Data (Auto-Extraction)

Some metadata can be extracted directly from the imported analytical
data if the required columns are present:

``` r

mexp <- import_metadata_from_data(mexp)
```

This extracts sample annotations (e.g., `qc_type`, `batch_id`) and
feature annotations from the data table, if available.

### Importing via MSOrganiser

The MSOrganiser template lets you store all metadata in a single Excel
file (`.xlsx`):

``` r

mexp <- import_metadata_msorganiser(
  mexp, 
  path = "datasets/my_metadata.xlsx", 
  ignore_warnings = TRUE
)
```

See [Metadata
Import](https://slinghub.github.io/MRMhub/quant/articles/manual-06-metadata-import.md)
for a detailed walkthrough of the MSOrganiser workflow.

### Validating Metadata

Before processing, validate that your metadata is complete and
consistent:

``` r

assert_metadata(mexp)
```

See the [Metadata Validation
Tutorial](https://slinghub.github.io/MRMhub/quant/articles/tutorial-10-metadata-validation.md)
for a full walkthrough of common validation errors and how to fix them.
