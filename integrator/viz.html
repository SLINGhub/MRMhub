MRMhub-viz: Integration Visualizer

MRMhub-viz is a standalone, interactive tool for reviewing INTEGRATOR peak integration results and guiding the refinement of integration parameters.

MRMhub-viz is a standalone, interactive application for reviewing the peak-integration results produced by INTEGRATOR (see Running INTEGRATOR — Step 3). It is distributed as a self-contained executable (~10 MB), resides in the same folder as the MRMhub application, and is launched like any other application. Because it reads the binary results written to the misc/ folder during peak integration, Step 3 must have been run at least once before the visualizer can display a dataset.

What it displays

The transition to be inspected is selected from the dropdown menu in the top-left corner. For the selected transition, the extracted ion chromatograms of the individual samples are shown together with the detected peak and its left and right integration borders, so that the integration can be reviewed across the entire analytical sequence at a glance. Moving the pointer over a chromatogram reports the exact retention time at the cursor — the value used when defining fixed peak borders in the transition list (see Input Files — Transition list).

The review → refine loop

MRMhub-viz is the inspection half of an iterative loop between visual review and parameter adjustment. Automated integration is rarely optimal for every feature on the first pass; the visualizer identifies where it fails, and the input files are adjusted to correct it. A typical cycle proceeds as follows.

  1. Inspect. Step through the transitions and confirm that the intended peak is detected and correctly bounded, both in the reference samples and across the sequence. Look for missed peaks, co-integrated neighbours, truncated tails, and failures of retention-time tracking.
  2. Diagnose. Relate each problem to the setting responsible for it — a missed peak to RT_tol or RT_shift, a co-integrated neighbour to peak_width, an untracked retention-time jump to RT_shift_bound (see Effects of the key settings).
  3. Refine. Adjust the global parameters in param.txt, or add per-feature overrides in the transition list (peak width, uniform_width, fixed integration bounds) for the problematic minority. Individual peaks that resist automated integration can also have their borders edited directly in RT_matrix.csv.
  4. Re-integrate. After a change to param.txt or the transition list, re-run peak finding (Steps 1–2) followed by integration (Step 3); when only RT_matrix.csv has been edited, re-run Step 3 alone. Reload the dataset in MRMhub-viz and repeat until the integration is satisfactory.
Tip

Refine globally first, then per-feature. Tune param.txt so that the majority of peaks integrate correctly, and reserve transition-list overrides and fixed borders for the remaining difficult peaks. Confirm every change in MRMhub-viz before re-integrating the whole dataset — see the peak-width recommendations.

Warning

Re-running Step 2 overwrites RT_matrix.csv. Any manual edits to the integration borders are lost when peak finding is re-run. Make manual RT_matrix.csv adjustments only once the automated integration is otherwise final, then run Step 3 (see Running INTEGRATOR — Step 2).
